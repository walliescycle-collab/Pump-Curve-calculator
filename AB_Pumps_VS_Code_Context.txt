1. PROJECT PURPOSE AND CURRENT DELIVERABLE

Build a public Streamlit application for AB Pumps to plan shaft-driven borehole
test-pump installations. Operators calculate total head, select pumps that can
meet every test step, inspect pump/system curves, estimate diesel engine size,
and compare measured pump performance with the expected curve.

The user requested a Jupyter-based workflow. The agreed implementation is an
editable Jupyter notebook plus a deployable Streamlit app using the SAME Python
calculation module. Do not duplicate the equations in the two interfaces.

Delivered archive: AB_Pumps_Streamlit_Project.zip (about 12.6 MB), containing
the ab_pumps folder. This context file is a separate handover; it was not inside
the original archive. Keep the complete extracted folder, including sources/.
There is no known GitHub repository or published app for this pump planner yet.
Another AB Pumps Streamlit project discussed elsewhere is a separate project.

2. CONFIRMED USER REQUIREMENTS — PRESERVE THESE

- Metric units: yield L/s, head/length metres, diameter mm, absorbed power kW.
- Four head terms: pumping lift, column friction, discharge elevation difference,
  layflat friction.
- Default conservative pumping lift equals pump installation depth: water may
  be drawn down to the pump. Do not require separate lift entry by default.
- Each test step nevertheless has its own pumping water level. An optional
  mode uses these individual levels instead of full installation depth.
- Column friction always acts over full installed column length.
- Discharge elevation means height difference between borehole and hose outlet.
  Optional two-coordinate terrain lookup is wanted; manual entry must work.
- Ignore fittings, outlet pressure and discharge velocity head.
- Consider only shaft-driven columns, nominal 40, 50, 65, 80, 100 and 150 mm.
- Support flow calculations up to 60 L/s and flag excessive velocities.
- PVC layflat nominal 50, 65, 80, 100, 150 and 200 mm; desired chart range 1–60 L/s.
- Default four test steps; allow up to 24. Both entered yield and entered
  pump-shaft RPM modes are required.
- “Suitable” means a pump meets ALL requested steps within its head, speed,
  power and borehole limits. Explain rejected and conditional results.
- Pump-shaft RPM only as the operator's pump speed. Diesel drive only.
- Recommend Deutz FXL912-series engine size for the installation, including
  maximum expected yield and the peak power requirement over all steps.
- Use old AB quick-reference table as historical pump/column/engine guidance.
- Include WASA models WA16-2 upwards from the supplied catalogue.
- Retain handwritten DW aliases from the supplied sheets.
- For GW9602 use a 150 m maximum head. Keep GW5406 provisional sheet as supplied.
- Include an expected-versus-actual RPM performance check at measured yield/head.
- Include notebook, deployable app.py, Excel/CSV downloads and curve downloads.

4. ENGINEERING METHODS IMPLEMENTED

4.1 Total head
H(Q) = lift + column_loss(Q) + discharge_elevation + layflat_loss(Q).
Full-depth mode: lift = installation depth.
Individual-level mode: lift = that step's pumping water depth below ground.
Individual water depth cannot exceed installed pump depth.
No well drawdown-versus-yield model is fitted; water levels are supplied inputs.
Negative discharge elevation is allowed; gravity/siphon regimes are flagged.

4.2 Column friction
40/50/65/80/100 mm curves are manually read representative points from the
supplied CEMO rising main / shaft & bearing friction chart. Source flow is
interpreted as m3/h, loss as metres per 100 m. The 40/50 mm lower panel follows
the sheet's m3/h convention; verify this interpretation if better documentation
becomes available.
Convert L/s to m3/h by multiplying by 3.6.
Interpolate positive points in log(flow)-log(loss) space.
Multiply loss per 100 m by installed length / 100.
At zero flow, friction loss is zero.
Outside chart bounds, extend from the nearest endpoint using Q^2; flag this.

150 mm has NO supplied chart. It is an annular scaling estimate from 100 mm:
  d1=0.100 m, s1=0.025 m; d2=0.150 m, s2=0.040 m
  multiplier = ((d1^2-s1^2)/(d2^2-s2^2))^2 * (d1-s1)/(d2-s2)
This assumes equal friction factors and does not reproduce all bearing details.
Keep the estimate label; do not describe it as a measured CEMO curve.

Velocity uses nominal annular area, not verified internal diameters. Assumed
shaft diameters for 40/50/65/80/100/150 mm columns are 13/16/19/22/25/40 mm.
Default velocity review threshold = 3 m/s, not a universal permissible limit.

4.3 Layflat friction
Uses Rain-Flo table for 2/2.5/3/4/6 inch layflat, mapped to nominal metric
50/65/80/100/150 mm. Actual inflated internal diameter can differ.
US gpm -> L/s: multiply by 3.785411784/60.
Source psi per 100 ft -> metres per 100 m:
  multiply by [6894.757293/(1000*9.80665)] * [100/30.48].
Log-log interpolation between table points.
Outside table flow bounds, use endpoint-anchored Q^1.85 extension and flag it.
200 mm is estimated from 150 mm by multiplying loss by (150/200)^4.87.
Multiply rate by actual hose route length / 100.
These extensions and the 200 mm curve are estimates, not measured hose data.

4.4 Pump curves
These are positive-displacement pump sources. DO NOT substitute centrifugal
affinity laws Q~N, H~N^2, P~N^3 for the source-based interpolation.
Graphical sheets were manually read into representative head/flow/power knots;
they were not automatically traced pixel by pixel. Numerical NOV/DW tables
were transcribed. Source quality is retained in each pump record.
At a given RPM: piecewise linear interpolation along head values.
Between two RPM curves: linear interpolation between their values at that head.
Use bounded head AND RPM domains. Exact published speeds use only their own
head domain. Do not silently extrapolate pump flow or power.
Flow curves store m3/h; calculation/UI flow returns L/s. Power is absorbed kW.
GW9602 maximum head is explicitly 150 m per user instruction.

Yield mode: calculate system head at requested Q, then interpolate required RPM
at that head. Check source, drive, bore and power limits across all steps.
RPM mode: solve pump/system intersection with scipy.optimize.brentq over the
valid common domain, within 0–60 L/s. No valid root means an explained failure.

4.5 Engine and drive
Pump absorbed kW is interpolated from source power curves, not inferred solely
from hydraulic power. Hydraulic kW is separately Q(m3/s)*1000*g*H/1000.
Required engine kW = (pump kW + extra mechanical kW) / transmission efficiency
                     * diesel sizing factor.
Available engine kW = continuous output at engine RPM * availability fraction.
Choose smallest passing F3L912/F4L912/F5L912/F6L912 across the maximum requirement
of ALL steps. Missing power for any step means no complete engine recommendation.
Continuous table caps at 2300 engine RPM: 36/49/61/74 kW respectively.
Intermediate engine output is approximate chart interpolation from 1000–2300 RPM.
F4L912 lower tabulated 49 kW cap takes precedence over the higher graph endpoint.

Defaults: pump drive speed limit 1100 RPM; angle-drive rating 60 HP (~44.74 kW);
transmission efficiency 0.90; extra shaft loss 0 kW; diesel factor 1.33;
available-power fraction 0.90; engine speed 2300 RPM.
Engine RPM and pump RPM are DIFFERENT. Suitable gearing is required; no complete
gearbox/torque-transmission design is performed. User must enter actual drive
limits, particularly a small drive whose kW rating is absent from the old chart.
The 90% fraction is a user assumption, not an automatic altitude correction.
Running torque is 9550*(pump kW+extra kW)/pump RPM. Published minimum starting
torque is displayed when available; starting-torque adequacy is not certified.

4.6 Field performance comparison
Given measured Q, total differential head and actual pump-shaft RPM:
  expected RPM = curve RPM needed to deliver measured Q at measured head;
  RPM difference % = 100*(actual/expected - 1);
  expected Q at actual RPM = interpolated curve flow at measured head;
  flow difference % = 100*(measured/expected Q - 1).
Default comparison tolerance is 10%, user adjustable. Higher actual RPM than
expected implies below-curve performance for the stated Q/H. This is a comparison,
not a diagnosis of wear, leakage, bad instrumentation or water-level error.
Field head may be entered directly or calculated using observed pumping level.
Comparison tolerance never increases allowable operating limits.

6. API AND STATE CONVENTIONS

Read exact signatures in hydraulics.py before editing. Main entry points:
load_pumps(); column_loss(); layflat_loss(); velocity(); system_head();
curve_value(); required_rpm(); operating_point(); engine_options(); evaluate();
compare_actual(); terrain_elevations().
Installation and Drive provide validate() methods.
CurveRangeError distinguishes missing/out-of-domain curve data.
load_json() caches loaded datasets; restart process or clear cache after edits.

Steps are dictionaries: {'value': number, 'water_level_m': number}.
Mode is 'yield' or 'rpm'. evaluate() returns pump, status, reasons, conditions,
rows, required_engine_kw and recommended_engine.
Status values: 'Not suitable', 'Conditional', 'Suitable for planning'.
Reasons are failing limits; conditions flag estimates or unresolved information.
Each row can contain an error; downstream code must handle incomplete rows.

Setup JSON contains version, project, installation, drive, mode, steps and pump.
Use dataclasses.asdict() to serialize installation/drive. Sidebar restore callback
validates input, sets widget state, clears editor state, restores row count/mode
and selected pump. Review full save/restore with a real browser before release.
Data editor state keys include input_<mode>_<n>. Row-count widget keys depend on
the up-to-24 checkbox. Preserve edited values thoughtfully when changing modes.

Terrain endpoint: https://api.opentopodata.org/v1/srtm90m
Requests are user-triggered; only coordinate pairs are sent. Timeout 12 seconds.
Validates latitude coverage, response status and missing elevations. Manual
fallback exists. About 90 m terrain resolution cannot reliably establish small
height differences, hose route lengths or route high points. Live API operation
was not established by the automated tests; its response was mocked.

Downloads: test-step CSV, Excel workbook (steps, comparisons, installation,
drive assumptions, source), self-contained Plotly HTML, setup JSON, field-check
CSV, friction tables and source data. Plotly toolbar offers PNG export.
No shared database, login or permanent server-side project storage is included.
